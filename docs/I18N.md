# I18N

Internationalization facts and plan.

## Oracle behavior (revision `6b4a373e`)

- Locale resolution (`main.cpp:62-106`, bitcoin-qt derived):
  `QLocale::system().name()` → truncate at the last `_` for the base
  language → load order `qt_<base>`, `qt_<lang_TERRITORY>`, app `<base>`,
  app `<lang_TERRITORY>` from the `:/translations/` resource.
- Compiled catalogs (qrc aliases): bg ca cs de es it ja ko nl pl ru sk sv tr
  zh-CN. **Quirk:** `cachyos-kernel-manager_uk.ts` exists in `lang/` but is
  absent from the qrc — Ukrainian is never loaded. Preserved.
- `zh-CN` alias vs `QLocale` `zh_CN` mismatch is unwitnessed (court
  `i18n/locale-resolution`, gap-009).
- Desktop-entry translations exist for it and ja.

## Candidate plan

`crates/cachyos-kernel-manager-i18n` implements the Qt-compatible resolution
model (pure, tested). Phase 8 converts the upstream `.ts` catalogs into a
Slint-consumable catalog with provenance per string; courts cover base-only,
lang+territory, CJK, unknown, and C locales, plus truncation/rendering.
